# 28 秒实时开场 · 清晨篇

## 播放方式

正常运行主场景，在菜单选择“开始游戏”。没有任务存档时播放 28 秒开场；已有任务存档时直接进入原来的加载流程。项目目前保存的是任务进度，不保存猫的世界位置；本系统没有新建或覆盖玩家位置存档。

随时按 **Esc** 或点击右下角“Esc 跳过开场”。跳过会进行约 0.45 秒的镜头和声音过渡，再恢复操作；猫停留在当时的真实地面位置，不会突然传送到片尾位置。完整播放后，猫位于入户门前，使用原来的 E 开门继续探索。

反复预览：打开 `scenes/cinematics/OpeningPreview.tscn`，按 **F6**。它实例化真实主场景，复用真实玩家，且关闭这一预览会话的任务存档写入。也可以启动时传入 `--intro-preview`，但推荐 F6 预览场景，以免普通主场景结束后正常产生任务存档。`--skip-intro` 始终绕过开场；原有 `--autoplay` 和直接调用 `start_game()` 仍保留给测试/旧开发工具使用。

## 实际分镜

| 时间 | 画面与动作 |
|---|---|
| 0–6 s | 黑屏用 1.5 秒淡入；晨光中的真实入户花园，镜头沿曲线向猫靠近。复用待机与呼吸。 |
| 6–12 s | 低机位近景绕拍；复用现有 stretch，随后回到待机并轻微转头；10.4 秒附近播放原猫叫。 |
| 12–20 s | 猫沿真实曲线路径向入户门走去，实际行程约 3.82 m；根据碰撞后的实际速度驱动原四足步态，空间脚步声随爪步触发。低机位跟拍并拉开距离。 |
| 20–26 s | 猫停下并轻摆尾巴，镜头升高拉远；标题“哈基米模拟器”和“清晨 / 一段新的日常”淡入淡出，原创简洁配乐进入主旋律。 |
| 26–28 s | 电影摄像机平滑插值到玩家当时的第一人称摄像机；恢复日常太阳光和环境声，收起画幅及标题，恢复控制和 HUD。 |

镜头之间有意保留三个剪辑点；每个镜头内部使用曲线和缓动。片尾进入猫头之前，电影摄像机改用原第一人称角色过滤，避免看到猫头内部。

## 复用与新增素材

- 地图：现有 `scenes/villa.tscn` 的前庭、长椅、花草、入户门、别墅外立面和日光；没有改动地图资源。
- 角色：实际 `Miso` / `CharacterBody3D`，复用 `Calico`、47 骨骼和原有 IK 驱动，未另造替身。
- 动作：idle、stretch、walk、tailwag 和 meow 的下颌动作。没有睡眠动作，因此采用“站立伸展”重新设计，没有假装完成睡眠/起身动画；本次无需新增 Blender 动作。
- 音效：复用 `assets/meow.wav`、`assets/paw.wav`，使用跟随猫的 AudioStreamPlayer3D；原有 rain.wav 在开场中降低音量，交接时恢复。
- 配乐：新增 `assets/audio/opening_dawn.wav`，28 秒立体声原创简易合成器音符、和弦及短反射。它不是钢琴采样或管弦乐录音。峰值约 0.408、无削波样本；用户主音量设置保持有效。
- 画面：只为电影摄像机复制 Environment，做轻微暖色环境光；临时太阳光在结束时恢复。景深只用于近景，采用本摄像机独立 CameraAttributesPractical；兼容模式自动禁用。没有修改 project.godot 的全局渲染配置，没有开启雾和全局泛光。

## 系统与恢复流程

`scripts/cinematics/opening_cutscene.gd` 发出 `started`、`shot_changed(index)` 和 `finished(skipped)` 信号。通过 `bind_game(game, player, ui)` 注入对象；世界环境和太阳由主场景中的可导出节点引用指定。

播放时保存控制器开关、碰撞相关状态、角色动画状态、摄像机、太阳光、环境音量和菜单显示状态。只在开场期间关闭玩家自己的物理和输入回调，由开场控制器对真实 CharacterBody3D 调用 `move_and_slide()`，不会同时有两套代码写角色位置。没有修改玩家控制器、碰撞体或输入映射。

主游戏在开场期间保持 `started = false`，所以任务、地图和门交互不会把过场动作计入玩家进度。自然结束和跳过统一进入 `_finish()`，停止时间轴/音频并恢复状态；重复 Esc/点击不会重复结束。时间轴异常停止也会释放控制，另有超时保护。已有任务存档的格式校验、坏文件保护和自动保存由原任务系统负责。

## 在编辑器调整

1. 打开 **OpeningCutscene.tscn**。选中 `Morning`、`Wake`、`Follow`、`Reveal` 的 Path3D，用 Curve3D 的控制点/切线调整四段镜头路径。`Follow` 的曲线是以猫的初始位置为参考，运行时额外叠加猫移动的位移。
2. `ActorPath` 控制猫的平面路线；代码会用实际碰撞和重力落地。路线应放在可行走区域，避免直接越过高台或关闭的门。
3. 选择 `AnimationPlayer` 的 **opening** 动画。已有 `film_time`、`blackout`、`title_opacity`、`matte_amount`、`score_gain` 属性轨道，可直接调整黑屏、标题、画幅和配乐淡入淡出。
4. 总时长改变时，同时调整动画长度、`film_time` 最后一个值和根节点的 **shot_boundaries**。默认值是 `[0, 6, 12, 20, 26, 28]`：四镜开始点、交接开始点、片尾时间。配乐仍为 28 秒，需按新长度重新制作/替换。
5. 选根节点设置 **playback_policy**：无存档时播放 / 每次从菜单开始播放 / 关闭。**allow_skip** 控制跳过；**skip_action** 可选择已存在的自定义动作（Esc 固定可用）。**use_depth_of_field** 可关闭近景景深，**skip_blend_seconds** 控制跳过交接时长。
6. 主场景 `OpeningCutscene` 实例绑定了环境和太阳节点。换地图时需重新绑定这两个引用并调整路径，不必修改玩家脚本。

运行时会校验路径和镜头时间边界。镜头还会检测实际障碍并向猫一侧缩回，但编辑后仍应运行 F6 检查构图；自动防穿墙不等于自动设计好镜头。

`tools/build_opening_assets.py` 可以重建初始曲线、UI、时间轴和合成配乐。**手工修改场景后不要随意重新运行该工具，它会覆盖该场景中的编辑。**

## 验证与实际限制

- Godot 4.7.1 脚本解析、场景加载通过；真实 Vulkan / Forward+ 1280×800 运行至 28 秒并返回游戏。
- `playtest_opening.gd`：1813 项断言通过，包括完整流程、6 种跳过、重复结束防护、移动恢复、暂停/地图恢复、已有任务存档继续、时间轴中断、4:3 和超宽界面的跳过按钮位置。111 次摄像机球体检测没有碰撞；完整 GPU 播放时路线没有触发镜头防穿墙修正。
- 原 `playtest_ui.gd` 在 `--skip-intro` 模式通过；任务集成 36 项、任务逻辑 34 项、任务持久化 12 项测试通过。测试存档使用独立目录，未重置玩家存档。
- 波形检查通过：立体声、28 秒、无削波。已导出实际引擎录屏供观看。
- 游戏退出时仍可能打印原有 ObjectDB/资源释放警告；没有把它们宣称为本次已修复的问题。

当前美术上限来自现有地图和角色素材。本次实现的是实际可运行的电影式运镜、动画和交接，并非离线影视渲染。仍缺少专门睡眠/睁眼/起身动画、真实清晨鸟鸣/树叶风声以及录制级配乐。音效最终响度和完整镜头节奏需要在你的显示器与音响上试听确认；4:3、超宽已经验证 UI 布局，尚未逐帧人工检查所有宽高比的画面构图。

API 参考：[Godot 摄像机局部景深](https://docs.godotengine.org/en/stable/classes/class_cameraattributespractical.html)、[AnimationMixer 的物理时间轴](https://docs.godotengine.org/en/stable/classes/class_animationmixer.html)。
