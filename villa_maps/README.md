# 别墅地图

当前一楼原客卧已改为工作书房，二楼原次卧 B 已改为电脑房；部分内部区域 ID 保留旧名称以兼容存档。主线还包含地下室地图，当前玩法与目录入口见 [游戏 README](../README.md)。

主场景已实例化 `villa_map.tscn`。开始探索后，左上角显示跟随朝向的小地图；M 打开完整地图，M 或 Esc 关闭。完整地图打开时暂停猫的移动，避免同时触发 B 房屋总览、V 看猫等操作。

一层、二层、楼梯、花园共四张地图，位置标记使用猫脚底根节点的世界坐标。正常跳跃保持当前楼层，离开楼梯时根据支撑面和脚底高度切换。

## 合并后图片不显示的修复

PNG 和 `.import` 文件属于项目资源；`.godot/imported/*.ctex` 是每台电脑自己生成的缓存。仅拉取仓库后直接启动游戏，新增图片可能尚未生成缓存，原先直接 `load()` 会失败。

`map_textures.gd` 现在优先加载已导入资源；若检测到 `.import` 指向的本地缓存缺失，则读取仓库中的 PNG 字节生成纹理。导入完成后自动恢复正常资源加载，地图纹理只加载一次并缓存。正常开发仍可先用 Godot 打开 `project.godot`，等待资源扫描完成，不要将其他电脑的 `.godot/` 目录提交到仓库。

## 文件

- `layout.json`：四张地图的世界坐标范围、房间多边形和图片路径。
- `map_hud.gd`：楼层识别、资源缓存、玩家位置、M / Esc 输入和界面状态。
- `map_canvas.gd`：二维地图、房间高亮、方向和位置标记绘制。
- `map_textures.gd`：兼容缺少本地导入缓存的纹理加载。
- `assets/runtime/`：游戏实际使用的十二张图层。
- `assets/` 根目录：保留原始高分辨率基础、地面、文字与结构图层，便于后续地图制作。
- 当前房间高亮直接使用 `layout.json` 的多边形绘制，已清理不再读取的遮罩和高亮图片，以及重复的合成预览图。
- 游戏内界面示例见 `../previews/ui/hud.png`。额外地图截图可运行 `tools/capture_map.gd` 重新生成，输出到忽略提交的 `screenshots/maps/`。

平面布局变化时需要同步更新 `layout.json` 和地图图片；当前默认房屋根节点位于世界原点。
