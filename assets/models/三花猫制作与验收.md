# 三花猫角色 · 制作与验收

2026-10-16，Godot 4.7.1 / Blender 5.2.2 LTS。

## 交付与入口

- 游戏仍实例化 `scenes/calico.tscn`，控制器仍是 `scripts/player.gd`。
- `scenes/cat_studio.tscn` 是可旋转、可切换动作的模型检查场景。在 Godot 打开后按 F6，鼠标拖动旋转、滚轮缩放、1–8 选择动作，B 看骨架、C 看灰模。
- `assets/models/authoring/calico.blend` 是可继续编辑的 Blender 文件，含蒙皮、UV、打包贴图和 8 个 Action。`authoring/.gdignore` 防止 Godot 自动把建模源文件再导入一遍。
- `assets/models/calico_rigged.glb` 是 Blender 导出的 glTF 2.0 成品，含 47 根骨骼、8 段动画和 3 套 PBR 材质。
- `previews/calico/` 保存 Godot 实际渲染的正、侧、背、动作及游戏画面。

## 制作方式与模型结构

在原来的连续猫身网格、骨骼命名和四肢 IK 基础上修改，没有换成不兼容的角色。Blender Python 负责放松表面、校准体型、保留蒙皮权重、控制三角面数量和重新展开 UV。根据模型表面坐标烘焙不对称三花花纹、短毛细节、虹膜细节及粗糙度，而非直接使用参考图的纹理展示。

身体、头、四肢和耳壳沿用连续主体；弯曲尾巴在尾根嵌入身体，独立眼球、眼睑、鼻口、胡须、内耳和脚垫与对应骨骼绑定。没有额外悬浮的花纹网格，也没有全身毛发粒子。

单位为米，Y 向上，面向局部 -Z。静止模型肩部上缘测量约 **32.1 cm**，头宽约 **17.2 cm**，鼻尖至尾根约 **68 cm**，躯干约 **48 cm**，尾骨弧长 **30 cm**。

游戏保留原先 `cat_scale = 0.8` 的小猫比例，所以场景中是上述模型的 80%，原相机眼高约 22.4 cm。碰撞体尺寸、朝向、移动速度和输入映射均沿用项目已有设置。玩家脚本仅增加把竖直速度传给模型，供跳跃收腿使用。

## 动画

| Godot 动画名 | 已完成行为 |
|---|---|
| `poses/idle` | 站立、呼吸、轻微头部和耳朵动作 |
| `poses/walk` | 四足交替，支撑相脚爪保持在地面 |
| `poses/run` | 前后肢错相奔跑，抬腿和步幅增大 |
| `poses/jump` | 非循环收腿/伸腿动画；游戏中根据竖直速度控制姿态 |
| `poses/sit` | 后躯降低、脊柱抬起、前爪落地的坐姿和呼吸 |
| `poses/tailwag` | 13 节尾骨渐次摆动 |
| `poses/crouch` | 低伏 |
| `poses/stretch` | 前肢伸展 |

运行时继续使用原骨骼驱动与四肢 IK，并加入约 0.18 秒切换过渡。Walk/Run 的相位根据移动速度推进。动画库和 GLB 中也有可独立播放的烘焙动画。

游戏中 V 保持原来的第三人称查看功能，原 WASD、奔跑、跳跃、低伏均可用。Sit 和 TailWag 可以在模型检查场景或 AnimationPlayer 中播放；没有新增游戏按键，也没有擅自改变输入映射。

## 实际验证

- `tools/validate_cat.gd`：通过。验证 47 根骨骼、逆绑定、权重、3 材质、8 段动画；采样 183,168 次变形位置，没有非有限坐标或炸模。采样的脚爪最低高度约 0.00019 m，没有穿过地面。
- 同一验证工具将 Blender 导出的 GLB 再加载进 Godot，并逐段播放动画检查所有骨骼位置：通过。
- `tools/playtest_calico_game.gd`：通过。实际发送 V、移动、奔跑、跳跃输入，验证第三人称移动、动作选择、跳跃落地和第一人称恢复。
- Godot Vulkan 真实渲染了正面、左侧、右侧、背面、坐下、行走、奔跑和跳跃；也保存了主游戏第三人称画面。
- `git diff --check`：通过。

当前工程的原有回归测试并非全部通过：`playtest_map_stairs.gd` 的右侧贴边路线受阻（其余 6 条路线通过）；`playtest_villa.gd` 的旧跳跃测试点峰值约 0.132 m（19 扇门、16 个门洞、楼梯主线通过）。将玩家脚本替换为本次修改前的备份再次测试，得到相同失败结果。这两项作为已有地图/测试位置问题保留记录，不能宣称整套地图测试全部通过。

主游戏退出测试偶尔仍打印已有的 ObjectDB/资源释放警告；独立猫模型验证没有此问题。

制作顺序：原解剖数据 → Blender 精修和展开 → `paint_calico.py` → Godot 导入纹理 → `build_cat.gd` → `export_cat.gd` → `finish_calico_blender.py` → Godot 重新导入/验证。可以继续编辑 `.blend`，但仅保存它不会自动更新游戏：主场景为兼容原控制器，仍使用同源的 `calico_high.res` 与 `calico_poses.res`。后续手动改动 Blender 骨架或网格后，还需要将改动同步至这个角色场景；单独的 GLB 可直接拖入 Godot 场景播放其动画。只有完整重建旧形体时，才向 `author_calico_blender.py --source` 提供备份中的原解剖数据目录。不要对新版本重复运行旧的 `refine_cat.py`，它会覆盖成旧模型。

## 当前限制

这是实际接入游戏的风格化短毛猫；没有实现写实毛束轮廓、面部表情 blend shapes 或专门的远景 LOD。短毛依靠表面纹理，极近距离仍能看出网格轮廓。四爪 IK 目前按角色局部地平面求解，尚未增加逐爪地形射线，因此站在台阶边缘时不能保证四个爪子都贴合不同高度的台面。已有坐姿和摆尾动作尚未接入任务交互或自动行为。

流程参考：[Blender glTF 导出 API](https://docs.blender.org/api/5.0/bpy.ops.export_scene.html)、[Godot GLTFState 图像处理](https://docs.godotengine.org/en/stable/classes/class_gltfstate.html)。
